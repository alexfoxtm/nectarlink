## Ranked gaps

1. **Live/queued transfer deduplication — best bounded next feature.** Existing `file-transfer` / `upstream-sync` roadmap scope explicitly retains this missing behavior. `core/nectarlink-core/src/transfer.rs:733-741` creates the live outgoing transfer using the queue item's exact ID and peer. `desktop/app/src/state.rs:606-657` updates queue byte counters and also inserts/updates a live TransferView; it retains both. `desktop/app/src/bridge/transfers.rs:270-286` projects all live views, while `desktop/app/src/transfers.rs:144-201` serializes all queue items. `desktop/app/qml/pages/HomePage.qml:2085-2089` renders queue items and `:2261-2263` independently renders TransferList. One logical send can therefore produce two presentations/sets of actions. This is source-supported behavior, not a current physical observation.

   Minimum useful implementation: choose a single displayed representation for exact `(peer, outgoing transfer ID)` matches. Do not dedup by name, path or bytes; unrelated peers and incoming transfers must survive. Keep the canonical queue record, retries, TTL and cancellation intact; keep live pause/resume, truthful rate/ETA and terminal Open/Reveal where available. Prefer live rendering while Running/Paused, persistent queue rendering for Waiting/Failed/Expired, and terminal transfer rendering after queue removal. A pure projection decision can drive the two current model outputs; no core schema or storage mutation is needed. Root should settle this precedence before coding so a hidden row does not remove an existing action. Expected ownership: `desktop/app/src/transfers.rs`, `desktop/app/src/bridge/transfers.rs`, possibly `desktop/app/src/state.rs` for a pure shared projection seam, and focused tests in the same modules. No Home visual redesign is necessary.

2. **Individual queued file rows are absent despite source metadata.** `core/nectarlink-core/src/store.rs:364-380` already retains `QueueItem.files: Vec<QueuedFileSpec>`; `desktop/app/src/transfers.rs:183-201` discards those names/sizes from the Qt JSON. `bridge/transfers.rs:208-215` exposes only `first and N more` and aggregate counts. User cannot inspect all members of an outgoing batch in the current queue. A later bounded extension can project name/folder/size and stable `(queue ID, member index)` rows, using existing metadata only. Do not advertise per-member percent/ETA: `core/nectarlink-core/src/transfer.rs:106-121` exposes only batch bytes, so member progress needs an explicit authoritative source change rather than division/inference. Expected ownership: transfers.rs, bridge/transfers.rs, existing queue presentation component/QML and its focused tests. This is larger than dedup and should not be combined accidentally.

3. **Mac-to-phone remote input has no implementation.** `desktop/app/src/mac/screen_share.rs:153-154` explicitly ignores all phone input. View-only screen sender source exists but READY is false at :28-29, pending native acceptance. Remote input is genuinely absent under `mac-screen-share`, while capture transport is implemented-but-unaccepted. This is not a safe next offline task: it needs separately chosen permission/admission/owner/Stop semantics plus native Accessibility and real input acceptance. Keep it off. Likewise `mac/media_sessions.rs:11-19` has no player enumeration and returns Unsupported; the current source claims no supported public route, and no external API verification was authorized. Do not manufacture media capability or use private routes.
